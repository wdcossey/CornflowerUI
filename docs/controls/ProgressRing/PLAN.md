# ProgressRing: plan

[#28](https://github.com/wdcossey/CornflowerUI/issues/28). The 8.1 ProgressRing: a control Avalonia doesn't have, so
Cornflower's own (`Cornflower.Controls.ProgressRing`, rung 5), with the phone's default style and template as the Wp81
theme's `ControlTheme`, and its `Active` storyboard run frame by frame. The worked example for the controls we own.

## Where the values come from

Every value below is read from the 8.1 Update 1 runtime's default style for `ProgressRing`,
`R:\cornflower-reference\flash-update1\xbf-json\progressring.json`, and the values of its keys from `themeresources.json`
beside it, which equal the SDK's `generic.xaml` and `themeresources.xaml` ([CLAUDE.md](../../../CLAUDE.md), "Reference
material"). What the phone's control works out in its own code is read from the reference app on the reference profile:

- the captures, run `20261108-1732-dev11`, committed in [`ref/wp81/ProgressRing/`](../../../ref/wp81/ProgressRing/README.md),
  with their tree dumps;
- `TemplateSettings` read through the API on all seven profiles (#72);
- the size threshold and the clock, `-Probe ringsize`, runs `20261111-2316-dev11` and `-2327-dev11` (B6, #84);
- the running dots, `-Probe ring`, run `20261110-0829-dev11` (#66).

All of them are in [`tools/refapp/README.md`](../../../tools/refapp/README.md). The numbers the tests use are written
out, with their sources, in `tests/Cornflower.Tests/Controls/ProgressRingReadings.cs`.

## The phone's template

`progressring.json`, `template.tree`:

```
Grid                          three rows: *, Auto, *
  Border "BackgroundOverlay"  RowSpan 3; Background, BorderThickness, BorderBrush: TemplateBinding; Opacity 0
  Grid "Ring"                 Row 1; Transparent; Width, Height {StaticResource ProgressRingThemeSize} (57.5);
                              MaxWidth, MaxHeight {Binding TemplateSettings.MaxSideLength, RelativeSource TemplatedParent};
                              H/V alignment: TemplateBinding H/VContentAlignment; FlowDirection LeftToRight
    Canvas  (E1R)             RenderTransformOrigin .5,.5; RenderTransform RotateTransform "E1R"
      Ellipse "E1"            Style ProgressRingEllipseStyle; Fill TemplateBinding Foreground
    … E2 to E5 the same
    Canvas "SixthCircle" (E6R) Visibility Collapsed
      Ellipse "E6"
```

`ProgressRingEllipseStyle`, in the template's `Grid.Resources`: `Width` and `Height` `{ThemeResource
ProgressRingElipseThemeSize}`, `Margin` `{ThemeResource ProgressRingElipseThemeMargin}`, `Opacity` 0.

So **the ring is 57.5 across whatever the control's size**: `Ring`'s size is fixed and only capped by `MaxSideLength`,
which can't be under 57.5 while `MinWidth` and `MinHeight` are. The capture confirms it: in a 412.08 × 107.92 ring,
`Ring` is 57.5 square at 177.08, 25.42, centred. `TemplateSettings.EllipseDiameter` and `EllipseOffset` are worked out
but the 8.1 template binds neither.

Each dot's canvas fills `Ring` and turns about its centre; its dot sits 7.5 in from the canvas's top left, so 18 left
of and 18 above the centre, at 25.46 from it. A positive angle turns it clockwise.

## The Active storyboard

`progressring.json`, `ActiveStates`, `Active`: `RepeatBehavior="Forever"`, no `Duration` of its own, so as long as its
longest child. Besides the two setters above, twelve tracks, two a dot:

- **Opacity** (`E1` to `E6`), `DoubleAnimationUsingKeyFrames` of `DiscreteDoubleKeyFrame`s: 1 at 0, 1 at 3.21 s, 0 at
  3.22 s, 0 at 3.47 s. So a dot shows from its begin time until 3.22 s after.
- **Angle** (`E1R` to `E6R`), `DoubleAnimationUsingKeyFrames` of `SplineDoubleKeyFrame`s at 0, 0.433, 1.2, 1.617, 2.017,
  2.783 and 3.217 s, with the `KeySpline`s 0.13,0.21,0.1,0.7; 0.02,0.33,0.38,0.77; none (a straight line);
  0.57,0.17,0.95,0.75; 0,0.19,0.07,0.72; none; 0,0,0.95,0.37.

  | Dot | Angles (°) |
  |---|---|
  | E1 | −110, 10, 93, 205, 357, 439, 585 |
  | E2 | −116, 4, 87, 199, 351, 433, 579 |
  | E3 | −122, −2, 81, 193, 345, 427, 573 |
  | E4 | −128, −8, 75, 187, 339, 421, 567 |
  | E5 | −134, −14, 69, 181, 331, 415, 561 |
  | E6 | −140, −20, 63, 175, 325, 409, 555 |

  Each dot 6° behind the one before, but E5's fifth key, 331, which is 8° behind E4's.

any repeat, has no value from the storyboard: opacity 0 from the style, so it isn't seen.

**The size threshold is the control's**, not the theme's: the phone's control decides `SizeStates` in its own code, as
it works out `TemplateSettings`. So `ProgressRing` raises `:large` from its laid-out size, with the threshold, 60, a
constant of the control, internal. It is the reference profile's reading (scale 2.4), in view pixels. Whether another
scale gives the same 60 isn't read: one `ringsize` run on device 7 (scale 1.5) would say.

**The cycle is the keyframes'**, 4.305 s, not the 4.13 s the emulator showed: B6 found the emulator's animation clock
runs about 4% fast against its stopwatch, and the storyboard's own time wraps at the keyframes' 4.305 s.

## How it runs

The storyboard runs in the theme, frame by frame on `CornflowerClock` (ADR 0003: a motion that must match frame by frame
is a timeline on the clock). Avalonia's own `Animation` can't be used for it and tested to the millisecond: Avalonia 12.1.4's
`MediaContext` pulses its animation clock from a private `Stopwatch`, so animations run on real time even under the
tests' manual render timer.

- `PhoneKeyframeTrack` (internal to Wp81) is one `DoubleAnimationUsingKeyFrames` evaluated as WinRT does: nothing before
  its begin time, discrete keys as steps, spline keys through their `KeySpline`, the last value held after. Times are
  ticks, so a key time compares exactly. Its `KeySpline` solves the Bézier to 1e-12: Avalonia's
  `KeySpline.GetSplineProgress` approximates, up to 0.0006 off the curve, which is 0.09° on these keys.
- `PhoneProgressRing` (internal to Wp81), turned on by the theme's setter, runs the twelve tracks while the ring is
  active, in a window and templated, from the storyboard's start; it sets each dot's angle on its canvas's
  `RotateTransform` and its opacity at animation priority when it changes, and gives them back when it stops.
- `Cornflower.Controls` gives the theme its clock (`InternalsVisibleTo`), as `Tilt` uses it.

The control has no animation and no visual opinion: an app's own theme can draw it any way.
