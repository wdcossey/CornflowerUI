# Cornflower — CLAUDE.md

**Cornflower** is a faithful reproduction of the Windows Phone design languages for AvaloniaUI,
mobile first. It themes Avalonia's own controls and adds the controls Avalonia lacks. The first
era is Windows Phone 8.1.

This file states **only what exists**. A plan, a proposal or an intention does not go here.
Plans live in `docs/ROADMAP.md`; process in `docs/PROCESS.md`; decisions in `docs/decisions/`; design in `docs/ARCHITECTURE.md`.

## Persona

Principal engineer on an AvaloniaUI theme and control library. You care about fidelity to the
reference, correctness on touch devices, and never declaring something that doesn't work. You
measure the reference before writing a line, and you build and test before every commit.

## Avalonia facts the code relies on

Each is held by a test, most of them spikes ([docs/spikes](docs/spikes/README.md)); an upgrade that changes one turns it red.

- **A control picks its `ControlTheme` once, when it joins a logical tree.** Install themes before setting content, and put `Wp81Theme` after `SimpleTheme`.
- **A missing `ControlTheme` fails silently**: a `ContentControl` gets a bare `ContentPresenter`, a `TextBox` gets nothing and measures 0×0. Every control and subclass has a test that it is templated by the theme.
- **A subclass gets no theme of its own.** It needs a `ControlTheme` with `BasedOn` the base's, or a `StyleKeyOverride` returning the base type.
- **`LetterSpacing` is in DIPs.** WinRT `CharacterSpacing` n is n × `FontSize` / 1000.
- **A weight word in a family name overrides `FontWeight`, and one font collection has one face per weight.** "Selawik Semilight" is asked for as "Selawik" at 350, and the first face loaded at 300 wins that slot. Selawik Semilight's file says 300, so it is bundled alone in `Fonts/SelawikSemilight/`. Held by `tests/Cornflower.Tests/Fonts/SemilightTests.cs`.
- **A line is the font's `hhea` line**, unless `OS/2` sets `USE_TYPO_METRICS`; a larger `LineHeight` is split evenly above and below. Selawik's line is 1.200 em; the phone's Segoe WP line is 1.330 em. Held by `tests/Cornflower.Tests/Fonts/LineMetricTests.cs`.
- **Avalonia's animation clock is internal.** `Transitions` and `Animation` run on real time, so a test checks a transition at its end value; a timeline a test must assert by the millisecond is a frame loop on `CornflowerClock`. Held by `tests/Cornflower.Tests/Harness/CornflowerClockTests.cs`.
- **Headless frames move only on a forced render tick.** Avalonia.Headless drives the render loop from a real `DispatcherTimer`, and MediaContext has a real 16 ms timer of its own, so any `RunJobs` could compose a frame or run a frame callback by timing. `ManualRenderTimer` (installed by `TestApp`, by reflection: the timer types are `[PrivateApi]`, their members hidden from the reference assemblies) stops both and puts them under `AvaloniaHeadlessPlatform.ForceRenderTimerTick()`, which the headless input helpers and `CaptureRenderedFrame` also call; each tick is 1/60 s. Frame callbacks run in MediaContext's render pass, a dispatcher job, which waits for a tick while a frame is in flight (committed, not yet composed) or a callback asked for from another is waiting; otherwise the next `RunJobs` runs it. Avalonia's `Transitions` and `Animation` move only on ticks too. Held by `tests/Cornflower.Tests/Harness/ManualRenderTimerTests.cs`.
- **A `RenderTransform` can be a perspective matrix, and hit testing goes through it.** Avalonia draws a 3 × 3 matrix with perspective terms about `RenderTransformOrigin`, and `TranslatePoint` and `GetPosition` invert it, in single precision. So a part tilted by its `RenderTransform` isn't hit where it's drawn sunk away, and a `Button` whose template root is tilted misses a tap at its very edge, on the side pressed away from the eye. `Rotate3DTransform` is such a matrix with its eye over the origin at `Depth` and no depth offset, its angles turning opposite to `PlaneProjection`'s. Held by `tests/Cornflower.Tests/Behaviours/TiltModelTests.cs` and `TiltTests.cs`.
- **No change is raised for a value set under an animation-priority value, and only the local or styled one is its base value.** Under the tilt's `RenderTransform`, a part's new local or styled transform raises no `PropertyChanged` (a transform changing in place raises `Changed`), so the tilt sees it at its next frame; `GetBaseValue` reads it. Of two animation-priority values the later shows. Held by `tests/Cornflower.Tests/Behaviours/TiltTests.cs` (`A_Change_To_The_Parts_Own_Transform_Mid_Press_Is_Drawn`, `An_Own_Transform_At_Animation_Priority_Isnt_Composed`).
- **A `LineHeight` shorter than the font's line keeps the baseline at the font's ascent**, so the line is cut from below and the descenders draw past it; a `TextBlock` clips to its bounds unless `ClipToBounds` is off, and a negative `Padding` takes from its size. Held by `tests/Cornflower.Tests/Fonts/LineMetricTests.cs` and `tests/Cornflower.Tests/Controls/TextBlockTests.cs`.
- **When a `ControlTheme` goes, its values are unset from the property registered last, and a handler that takes another value away while the last is unset stops the rest.** They keep the old theme's values with no change raised. So `PhoneTextLine` and `PhonePasswordKeyboard` don't act inside a change at `Unset` or `Inherited` priority: they work their values out from the dispatcher, ahead of layout (no test reaches the trap through `PhonePasswordKeyboard`, as a `TextBox` has values of properties registered later). Held by `tests/Cornflower.Tests/Spikes/UnsetPassTests.cs`, and `TextBlockTests.A_Value_A_Derived_ControlTheme_Sets_Wins_Over_The_Styles` and `A_Theme_Setting_MaxHeight_And_BaselineToBaseline_Goes_Cleanly`.
- **Only a subclass can override what a `TextBlock`'s layout reads, and a coercion can't stand in for a value set at style priority.** `RenderCore` is private protected and `Render` sealed, and `Layoutable`'s layout events come after the pass. A coercion sees the priority before a value comes in, and none when styles are applied again; a coerced default stays in the store and stops inheritance. A presenter makes its text from the tree's data templates first, then Avalonia's `AccessText` or `TextBlock`. So `PhoneTextLine` writes `Padding`, `LineHeight` and `LetterSpacing`. Held by `tests/Cornflower.Tests/Spikes/TextLineHookTests.cs`.
- **`TextInputOptions` inherit, and a style setter whose binding gives no value still hides an ancestor's.** So a setter bound to `PasswordChar` can't set them for masked boxes alone (and XAML has no selector for "any `PasswordChar`"); `PhonePasswordKeyboard` sets and takes them from code. Held by `tests/Cornflower.Tests/Spikes/KeyboardOptionsTests.cs` (spike 8).
- **Every global style rule is checked against every element; a `ControlTheme`'s rules only against the controls using it.** So a control's styling goes in its `ControlTheme`, and the theme's global rules are budgeted. Held by `tests/Cornflower.Tests/Performance/StyleBudgetTests.cs`.
- **Layout rounds a size up to the raw pixel grid**, where the phone rounds to the nearest: at 1.8 a 109-wide Button is 109.44, the phone's 108.89. A recorded deviation (ADR 0003). Held by `tests/Cornflower.Tests/Harness/SceneTests.cs`.
- **A `DynamicResource` on a brush's `Color`, inside a theme's dictionary, follows a key redefined in `Application.Resources`.** An app sets the accent this way, by defining `SystemColorControlAccentColor`. Held by `tests/Cornflower.Tests/Tokens/TokenTests.cs`.
- **Skia applies a visual's opacity to each thing it draws, not to the visual as one layer, unless `RenderOptions.RequiresFullOpacityHandling` is set on its parent.** So a `Border` at 0.4 draws its background, its border and its content each at 0.4, overlapping. The ToggleButton theme sets it on its template's root, for the phone's `CheckedDisabled`. Held by `tests/Cornflower.Tests/Controls/ToggleButtonTests.cs` (`Checked_And_Disabled_Is_The_Checked_Look_At_Four_Tenths`, red without it).
- **Avalonia's `TextBox` sets its `ScrollViewer` part's `MinHeight` and `MaxHeight` in every measure** (for `MinLines` and `MaxLines`, in lines of its own `LineHeight`), and its `HorizontalScrollBarVisibility` at style priority, so a theme's values for them on those don't hold. Held by `TextBoxTests` (`The_Bounds_Are_The_Dumps`, `MaxLines_Counts_The_Phones_Lines`).
- **Hit testing reaches no part outside its control's bounds**: a template part with negative margins past the control's edge isn't hit there, even inside the parent. Held by `ToggleSwitchTests.Only_The_Switch_Takes_The_Finger`.
- **Headless, a `DispatcherTimer` ticks in a pushed `DispatcherFrame`, in real time.** `RepeatButton` repeats on its own timer, which `TestClock` can't reach, so its tests push a frame until the repeats come. Held by `tests/Cornflower.Tests/Controls/RepeatButtonTests.cs` (`A_Held_Press_Repeats_After_The_Delay_At_The_Interval`).

## Reference material

Microsoft's Windows Phone 8.1 SDK files (default templates, theme resources, API metadata, design
files, fonts) are the reference. They are read as a specification and **never enter this
repository**. They live outside it, in `R:\cornflower-reference\` on the maintainer's machine.
The files taken from the emulator's image are in `flash-update1\` (8.1 Update 1, `6.3.9651.0`, the image the
reference profiles run: its DLLs and registry, and its runtime templates as XBF and as XAML and JSON
decompiled from them); that is the reference. `flash-vhd\` is the 8.1 RTM image, not the reference. Update 1's
runtime templates and theme resources equal the SDK's design files.

## Rules

1. **Build gate.** `dotnet build` with 0 warnings and `dotnet test` green before every commit.
2. **One control or family per PR.**
3. **No dead props.** Declared ⇒ works ⇒ has a test that fails without it.
4. **Tests assert the reference's behaviour**, from a capture or measurement named in the PR.
5. **No literal colours outside a theme's `Tokens/`.** No visual opinion in `Cornflower.Controls`.
   `LiteralColourGuardTests` fails on a literal colour in any file under `src/` outside a `Tokens/`
   folder: in XAML, a value Avalonia parses as a colour, outside comments; in C#, a hex string,
   `Color.From*`, `Color.Parse`, `Colors.*` or `Brushes.*`. `Transparent` is allowed.
6. **No Microsoft fonts, templates or SDK files in the repo.** Every template is written new.
   `MicrosoftFileGuardTests` fails on any file git would commit that is a font not on its
   allowed list, is named `generic.xaml`, `themeresources.xaml` or `*.winmd`, or has the content of a
   Microsoft file in the reference folder: pulled from the VM or an emulator image, or decompiled or
   converted from one. It matches byte for byte and, for text, with the BOM and line endings as git
   stores them. The hash list covers everything in the folder but our own output, and is regenerated with
   `node tools/guard/hash-reference.js <reference folder>` whenever more files are pulled.
7. **Add files, don't register them.** A control's theme file is found by auto-discovery; a PR
   for one control touches no shared file, except to delete its own lines from
   `tests/Cornflower.Tests/Completeness/Holes.txt`, which `HolesTests` requires, and to raise a
   style budget limit (rule 8). One standing exception: `Cornflower.Controls.csproj`'s
   `InternalsVisibleTo Cornflower.Themes.Wp81`, for the internals a theme needs to run Cornflower's
   timelines (today `CornflowerClock` and `KeySplineCurve`), accepted on the maintainer's behalf on
   2026-11-12 (#88): the two packages ship together, and the alternative is a public timing API
   apps would come to depend on. Any other change to a shared file in a control's PR (as #93's to
   `HoleParts.cs`) is the maintainer's to approve, case by case, and its PR says so.
8. **Style budget.** `StyleBudgetTests` fails when `Wp81Theme`'s global rules pass their limits. A
   PR that needs more, a control's included, raises the limit in `StyleBudgetTests` on purpose and
   says so in its description, with the new total; past the checkpoint, measure on the phone first
   (`docs/performance/README.md`). The README's table catches up at the roll-up.
9. **This file is ground truth.** Update it in the PR that makes a statement here true.
